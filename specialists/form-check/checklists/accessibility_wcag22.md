# WCAG 2.2, Accessibility Review Checklist

Apply to every browser-rendered web app, document, or component library. WCAG 2.2 supersedes 2.1; 4.1.1 Parsing is obsolete and removed.

## What's new in 2.2 (vs 2.1)

| Criterion | Level | Description |
|---|---|---|
| 2.4.11 Focus Not Obscured (Minimum) | AA | Keyboard focus indicator not entirely hidden by other content |
| 2.4.12 Focus Not Obscured (Enhanced) | AAA | Focus indicator not obscured at all |
| 2.4.13 Focus Appearance | AAA | Focus indicator meets contrast + size minimums |
| 2.5.7 Dragging Movements | AA | Drag actions have a single-pointer alternative |
| 2.5.8 Target Size (Minimum) | AA | Pointer targets ≥ 24×24 CSS px (with documented exceptions) |
| 3.2.6 Consistent Help | A | Help mechanisms appear in same relative order on each page |
| 3.3.7 Redundant Entry | A | Don't ask users to re-enter info they've already provided in the session |
| 3.3.8 Accessible Authentication (Minimum) | AA | No cognitive function tests for authentication unless an alternative exists |
| 3.3.9 Accessible Authentication (Enhanced) | AAA | No cognitive function tests for authentication, period |

## Minimum review process

1. **axe-core / Lighthouse / pa11y** automated scan, catches ~30–40% of issues (the rest require human review).
2. **Keyboard-only walkthrough** of every primary user flow.
3. **Screen-reader walkthrough** with at least one of NVDA / JAWS / VoiceOver / TalkBack.
4. **Reduced-motion / high-contrast / 200% zoom** rendering check.
5. **Color contrast** verified per text size (1.4.3 AA = 4.5:1 normal, 3:1 large).

## Per-component review (component library / design system)

For each component, document:
- Roles and ARIA states used
- Keyboard interaction model (Tab / Arrow / Enter / Space / Escape behavior)
- Focus management (where focus goes on open/close/error)
- Screen-reader announcement (what the user hears)
- Reduced-motion alternative
- Touch-target size (24×24 CSS px minimum)

Reference: W3C ARIA Authoring Practices Guide (APG).

## Vibe-impossible reminder

Decisions about ARIA pattern selection, focus-management semantics, and screen-reader copy require qualified review. AI may *implement* against a documented pattern but should not *select* the pattern unsupervised, see `rubrics/vibe_safety_map.md` Bucket 4.

## Output

Per finding:
- WCAG criterion (e.g. "2.4.11 AA")
- Affected component / page / flow
- Reproduction (assistive tech + steps)
- Proposed fix
- Severity (P0 = blocks user / regulatory; P1 = significantly degrades; P2 = polish)

## Anti-patterns

- Relying solely on automated scanners (catches ≤40% of issues).
- "Accessibility pass" done at end-of-project (refactor cost = 10× vs incremental).
- ARIA patterns invented without consulting APG.
- "Accessible" alt text autogenerated by a model on user-uploaded images without review (LLM09:2025 misinformation risk on accessibility-critical content).
- Skip links hidden visually but not focusable.
- Modal dialogs that don't trap focus.
