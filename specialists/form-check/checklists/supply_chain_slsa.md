# Supply-Chain Hygiene + SLSA Mapping

Treat the build pipeline as a security boundary. Recent attacks (Shai-Hulud / Mini Shai-Hulud, Sept 2025–May 2026) exfil shared CI tokens via post-install scripts; the lesson is "shared CI secrets = single point of failure."

## Threat model (current as of 2026-05)

1. **Slopsquatting** (SLOP-arXiv): LLMs hallucinate package names; attackers register them; devs copy-paste AI output.
2. **Typosquatting** (`requets` for `requests`).
3. **Dependency confusion** (private package name registered on public registry).
4. **Compromised maintainer accounts** (account takeover or stolen 2FA).
5. **Wormable post-install / post-publish scripts** (Shai-Hulud pattern: install → exfil tokens to public GitHub repos → use stolen tokens to publish trojaned versions of *other* packages the maintainer owns).
6. **Cross-ecosystem propagation** (Mini Shai-Hulud May 2026: npm + PyPI).

## Mandatory hygiene (default mode)

| Control | Tool examples | Frequency |
|---|---|---|
| Lockfile with hashes | `uv lock --generate-hashes`, `pnpm-lock.yaml` w/ integrity, `gradle dependency-verification`, `Cargo.lock` | every change |
| Vuln scan | `pip-audit`, `npm audit`, `govulncheck`, `cargo-audit`, OWASP DC, Snyk, Socket.dev | CI on every PR |
| New-dep gate (slopsquatting) | manual: registry exists? author known? first-seen ≥30d? prior versions exist? | every dep-add |
| Post-install / post-publish scripts forbidden | `npm config set ignore-scripts true` (consider trade-offs); audit which deps require scripts | per dep-add |
| Token rotation | npm tokens, GitHub PATs, CI runner tokens, OIDC federation preferred over PATs | quarterly + on incident |
| 2FA on registry accounts | npm 2FA, PyPI 2FA, crates.io 2FA, Maven Central GPG | enforce org-wide |
| SBOM generation | CycloneDX or SPDX; ship per release | per release |
| Pinned base images | `python:3.12.4-slim@sha256:...` not `python:slim` | every Dockerfile change |

## SLSA Build Track levels (target)

Default-mode target: **Build Track L2**. Scale-up annex pushes toward L3+.

### Build Track L1 — Provenance exists
- Build process generates provenance metadata (build platform, source repo, build inputs).
- Tooling: most modern CI emits some; explicit format: in-toto attestations.

### Build Track L2 — Hosted build platform
- Build runs on a hosted CI (GitHub Actions, CircleCI, GitLab CI, Buildkite hosted) so the provenance is generated by a trusted party.
- Tooling: GitHub Actions OIDC federation + sigstore cosign signing.

### Build Track L3 — Hardened builds
- Build platform isolates each build (no leakage between concurrent builds).
- Provenance is unforgeable by tenants.
- Tooling: hosted CI with secure runner isolation; reproducible builds where possible.

### Build Track L4 — (planned / partial)
- See SLSA spec; not currently widely deployable. Track for future.

### Source Track / Dependencies Track — Active development
- Source track: tag protection, signed commits.
- Dependencies track: how deps are consumed; transitive provenance.

## Slopsquatting check (ritual on every dep-add)

For each new package, before adding to lockfile:

1. **Registry exists**: search the canonical registry; copy URL into the PR description.
2. **Author known**: not first-publication for this package; author has prior published packages.
3. **First-seen**: package was published > 30 days ago (Shai-Hulud waves typically detected within days; 30d is a soft buffer).
4. **Prior versions exist**: 0.x or 1.x with semantic-meaningful releases, not just a single 0.0.1.
5. **License clear**: spdx identifier; not "UNLICENSED" or missing.
6. **No post-install / preinstall script**: if present, audit the script line-by-line. Otherwise reject.
7. **Bus factor**: ≥2 maintainers OR foundation-backed (Apache, Eclipse, OpenJS, Rust Foundation, PSF).

If any check fails, document in PR description with explicit override rationale.

## Incident response (Shai-Hulud-class)

See `templates/runbooks/supply_chain_compromise.md`. Concrete steps:
1. Identify affected packages via dep graph + vendor advisories (Wiz, Aikido, Snyk, Socket).
2. **Rotate all tokens** (npm, GitHub PATs, CI secrets, registry creds) — Shai-Hulud's whole point is exfil.
3. Audit GitHub for repos named `Shai-Hulud*` belonging to org members.
4. Force-revoke GitHub Actions OIDC tokens.
5. Re-scan all built artifacts for known malicious post-install signatures.
6. Customer comm (template in runbook).
7. Postmortem with action items.

## CI starter snippet

```yaml
# .github/workflows/supply-chain.yml
name: supply-chain
on: [push, pull_request]
jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: pip-audit
        run: pip install pip-audit && pip-audit -r requirements.txt --strict
      - name: npm audit
        run: npm audit --audit-level=moderate
      - name: SBOM
        run: cyclonedx-py environment > sbom.json
        # upload as artifact; track per release
```

- Token rotation cadence documented
