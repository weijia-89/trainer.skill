This is the production-secrets-in-staging Red Flag and the time-boxed "just for a week" framing is the textbook environment-boundary failure mode that ends in real customer data flowing through a staging-grade environment. The end-to-end-test legitimacy does not justify the boundary violation, no matter how short the window.

Demand a Stripe sandbox alternative or a scoped key with restricted permissions instead of the production live key. Stripe publishes test mode credentials that exercise the full subscription flow with realistic webhook fidelity, and most other services have a scoped key option that limits the blast radius if the staging environment leaks. The legitimate alternative is to use Stripe test mode for the end-to-end test and to record the staging-to-prod handoff in a runbook, not to copy production credentials across the boundary.

The "just a week" framing is the rationalization the Red Flag was written to catch. One week is enough for a Sentry-or-Segment pipeline to ship production card data to a third-party analytics pipeline, enough for a staging-environment compromise to leak prod keys, and enough for the secret to be checked into a logs bucket that the team forgot about. Refuse the shortcut and demand the scoped alternative.
