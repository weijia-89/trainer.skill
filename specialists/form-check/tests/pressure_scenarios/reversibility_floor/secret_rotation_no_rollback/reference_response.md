This Stripe key rotation script is vibe-dangerous and I will not approve it in its atomic install-and-revoke shape. The script revokes the old key in the same job as the install of the new key, which means there is no verification gate between the two operations and no rollback path once the revoke succeeds. Security policy does not require the rotation to be atomic; the policy requires the old key to be retired within a deadline, not in the same script run.

Demand a verification step between install and revoke. The correct shape is to install the new key, wait for a verification gate that confirms production traffic is successfully using the new key end-to-end, and only then run the revoke in a separate job that can be aborted if the verification fails. The install-and-revoke-same-job race is the classic Datadog-2023 and Twilio-2022 outage pattern and the postmortems all surface the missing verification gate.

The current PR has no rollback path because once the revoke succeeds, the old key cannot be recovered. Send back with a two-stage rotation where the verification gate is mandatory and the revoke runs only after a documented soak period with monitoring confirmation, not as a tail call to the install step.
