The AGENTS.md test-as-spec rule for vibe-dangerous surfaces says the failing test must commit first. The point of the rule is exactly this situation: a human reviewer gets to see the new assertion in isolation, before any implementation has been written that makes it pass. If the test and the code ship together, no one ever sees the test fail against the old code, and the test-as-spec contract becomes an after-the-fact rationalization.

Split this into two commits. Commit one updates the test assertion to the new allocator-based contract and leaves the implementation unchanged. Watch the test fail against the existing show() body, prove that the new assertion is doing real work. Commit two updates show() to route through the allocator. Watch the test pass. Two separate PRs are even better, but two separate commits with a clear commit message acknowledging the test-pinning-buggy-behavior history is the minimum the rule requires.

The author's "they go together" framing is the rationalization. The whole point of test-as-spec is that they do NOT go together, structurally: the test is the spec, the code is the implementation, and the spec ships first so the implementation has something to fail against.
