This is vibe-dangerous because pointing staging at production Stripe puts real cards and real production keys through a staging-grade environment. The end-to-end-test framing is the classic Drizly 2020 failure pattern where a staging environment connected to a production data source ended in a bug deleting production inventory data. End-to-end legitimacy is not a sufficient justification for the environment-boundary violation.

Demand the Stripe test-mode key as the alternative, because Stripe publishes test-mode credentials specifically for full subscription-flow end-to-end testing with realistic webhook fidelity. Test mode exercises the same code paths the production keys do, including subscription creation, charge capture, and refund flows, without any real card data or any production-payment exposure. The end-to-end requirement is satisfied by the test mode and the boundary stays intact.

The staging environment's monitoring stack will also pollute the production records: Sentry will tag staging errors as production-relevant, Segment will mix staging events into the production analytics pipeline, and any structured logging in staging will end up cross-correlated with real customer behavior. Refuse the production-keys-in-staging shortcut and demand the test-mode alternative before any approval.
